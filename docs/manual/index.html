Conciliação bancária · Classificação · DFC

Do extrato bancário à Demonstração do Fluxo de Caixa

O Ledger lê os extratos CSV e OFX que a empresa já recebe do banco, descarta o que já foi importado, classifica cada lançamento por regras e monta a DFC do ano mês a mês, separada em Operacional, Investimento e Financiamento.

Para quem

Times financeiros de PMEs, com 10 a 15 usuários e dezenas de milhares de lançamentos por conta ao longo dos anos.

O que entrega

Uma grade de lançamentos conciliável, regras automáticas, a DFC anual em tabela dinâmica, um dashboard e exportação para CSV e Excel.

O que não é

Um sistema contábil. O saldo da DFC é o fluxo classificado acumulado no ano, começando de zero, e não o saldo real do banco.

Jornada

Fluxo do usuário

Cinco etapas, cada uma com uma tela no front e um módulo na API. Clique numa etapa para ver o que acontece por baixo.

Sistema

Arquitetura

Monorepo npm com três workspaces. A web e a API compartilham enums, a hierarquia da DFC, DTOs e validações por meio de packages/shared, que precisa ser buildado antes dos apps (npm run dev já faz isso em modo watch).

Módulo imports

Pipeline de importação

O arquivo é decodificado (UTF-8, com fallback para Windows-1252), interpretado, filtrado e deduplicado. Os lançamentos novos são gravados numa única transação, com tudo ou nada, e as regras rodam logo depois do commit.

Módulo classification-rules

Motor de regras de classificação

As regras ativas são ordenadas por priority desc, createdAt asc e resolvidas campo a campo. A categoria vem da primeira regra que bate e que define categoria. O fornecedor/cliente vem da primeira regra que bate e que define um, e só é aplicado quando o lançamento ainda não tem fornecedor. O motor considera apenas lançamentos PENDENTE e sem categoria.

PlaygroundTeste uma descrição contra as regras
mesma lógica de rule-matcher.ts
Os tipos Contém e Igual a comparam sem diferenciar maiúsculas, acentos e espaços repetidos, então "Energia Elétrica" bate com "ENERGIA ELETRICA". O tipo Regex usa o texto original, sem diferenciar maiúsculas. Uma regex inválida é recusada ao salvar.

Módulo dfc · packages/shared/dfc-structure.ts

Demonstração do Fluxo de Caixa

A DFC não é armazenada. Ela é calculada sob demanda: cada lançamento classificado soma o seu valor na linha mapeada pela categoria, e grupos, seções e resultados são somas dessas linhas. Os valores são positivos para crédito e negativos para débito, então todo subtotal é uma soma direta.

ExploradorTipo de categoria → linhas permitidas

Mesma regra de dfcLinesForKind(): a API recusa, por exemplo, uma categoria Receita mapeada em Dividendos, e o formulário só oferece as linhas compatíveis com o tipo.

O saldo inicial e o final são o acumulado do fluxo classificado dentro do ano, começando de zero, e não o saldo bancário real. O que ainda não foi classificado aparece na linha Não classificado, fora dos saldos, com link para a grade filtrada por uncategorized=true.

Módulo auth

Autenticação e sessão

Access token

JWT de 15 min, guardado só em memória no cliente (token-store) e enviado como Bearer.

Refresh token

JWT de 30 dias em cookie httpOnly (sameSite=none; secure em produção). O hash fica em refresh_tokens, com rotação a cada uso.

Rotação com detecção de reuso

sequenceDiagram
  participant B as Componente React
  participant W as api-client.ts
  participant A as API /auth
  participant D as refresh_tokens
  B->>W: apiFetch(rota)
  W->>A: rota com access expirado
  A-->>W: 401
  W->>W: refreshAccessToken() singleton
  Note over W: chamadas concorrentes esperam a mesma promise
  W->>A: POST /auth/refresh (cookie)
  A->>D: busca pelo jti
  alt token já revogado (reuso)
    A->>D: revoga todos os tokens do usuário
    A-->>W: 401 faça login de novo
  else válido
    A->>D: revoga o atual e grava replacedBy
    A-->>W: novo access + novo cookie
    W->>A: repete a rota original
  end
Nunca chame /auth/refresh direto de um efeito de componente. No React.StrictMode o efeito roda duas vezes, e o segundo refresh usa um token já rotacionado, o que dispara a detecção de reuso e derruba a sessão.

Rate limit: 100 requisições por minuto por IP no geral e 10 por minuto em register, login e refresh. A API usa trust proxy para ler o IP real atrás do Railway.

REST · JSON

Referência da API

Rotas com :companyId passam por JwtAuthGuard + CompanyAccessGuard. Rotas por :id carregam o recurso e verificam se o usuário pertence à empresa dele (assertUserBelongsToCompany). Os IDs citados no corpo da requisição são validados por common/domain/assignable.ts.

Local · Produção

Setup e operação

Rodar localmente

npm install
npm run docker:up                              # Postgres 16 na porta 55432
npm run prisma:migrate --workspace=apps/api
npm run prisma:seed --workspace=apps/api       # demo@conciliacao.dev / demo12345
npm run dev                                    # shared (watch) + api :3001 + web :3000

Testes

npm --workspace=apps/api run test        # unitários (parsers, motor de regras, DFC, guards…)
npm --workspace=apps/api run test:e2e    # e2e contra Postgres real (DATABASE_URL)
npm --workspace=apps/web run test        # api-client, token-store, toast, categorias
npm run lint
Nunca rode next build com o next dev ativo na mesma pasta, porque isso corrompe o .next (sintoma: 404 em _next/static/*). Pare o dev server, rode o build, apague apps/web/.next e reinicie.
